# allometry project

[under development] project repository for

> New allometric equations for urban trees. *In prep.*

repository contributors: Camille Pawlak, Trevor Ruiz, Julia Schedler, Reed Kenny, Kaviya Veerasingam

## Data availability

**What is shared.** The cleaned, location-free tree inventory used to fit every model in the paper (`wca_inventory_public.csv`), a per-species frost-free-days table (`species_frost_free_days.csv`), and a data dictionary ([PUBLIC_DATA.md](PUBLIC_DATA.md)) are deposited on Zenodo alongside the paper: [doi:10.5281/zenodo.22236551](https://doi.org/10.5281/zenodo.22236551). The public inventory is the output of the full preprocessing chain below (name cleaning → quality control → anomaly flagging) with coordinates and internal columns removed by `scripts/py/3_make_public_data.py`. It can be substituted directly for the private pipeline output to reproduce the models, coefficient tables, and figures (see [Reproducing results from the public data](#reproducing-results-from-the-public-data)).

**What is not shared, and why.** The raw tree records were provided by West Coast Arborists, Inc. (WCA), who agreed to the release of a subset of the inventory with per-tree location removed. The raw WCA export and every intermediate file upstream of the public release contain tree locations and are **not** included in this repository or the Zenodo deposit, for data-privacy reasons and under the terms of that agreement.

**Why the cleaning scripts are included anyway.** The preprocessing scripts in `scripts/py/` are provided so readers can see exactly how the raw records were cleaned, filtered, and flagged, even though they cannot be re-run without the raw data. The per-run logs in `data/processing-log/` record the row counts removed at each step.

**Notebooks.** `notebooks/` contains exploratory and draft analyses kept for transparency. They are not part of the reproducible pipeline, their outputs have been cleared, and file paths in them are placeholders (`PATH`). One notebook (`notebooks/ipynb/canopy_width_to_dataset.ipynb`) documents how canopy width was calculated. `notebooks/rmd/age_dbh_filters.Rmd` uses tree coordinates and **will not run on the public data**.

## Quick Start

Before running any Python scripts, install dependencies:

``` bash
pip install -r requirements.txt
```

Then run scripts from the repo root (these require the raw data; see [Data availability](#data-availability)):

``` bash
python scripts/py/0_clean_names.py
python scripts/py/1_quality_control.py
python scripts/py/2_anomaly.py
```

**For VS Code**: See [SETUP.md](SETUP.md) for automatic Python configuration.

## repository organization

High-level directories distinguish data files, notebooks/scripts, and outputs generated by code execution.

### Top-level folders

- `data/`: local datasets and run artifacts used by scripts/notebooks.
- `notebooks/`: mixed code/text formats (e.g., `.ipynb`, `.qmd`, `.Rmd`).
- `scripts/`: executable code (e.g., `.r`, `.py`).
- `rslt/`: results written by scripts (non-image outputs).
- `_zenodo/`: public data release built by `3_make_public_data.py` and `build-zenodo.sh` (local only; deposited on Zenodo).

### Data folders (important)

Raw/source datasets are **not tracked** and will **not be available publicly** with this repository (see [Data availability](#data-availability)). Contributors should obtain raw inputs through the project’s shared storage and place them locally under `data/_raw/` (or other underscore-prefixed directories).

Recommended structure:

``` text
data/
  _raw/                 # local-only raw inputs (NOT committed; NOT public)
  _processed/           # cleaned outputs used for downstream steps (often local-only)
  _reports/             # small QA tables meant for reading/diffing (CSV summaries)
  processing-log/       # per-script text logs from CLI runs (tracked; timestamped in file)
```

To run the data processing scripts, place the following files locally in:

`data/_raw/`

Required files (default filenames used by the scripts):

- **WCA export (raw tree records)**
  - `wca_All_SpeciesBotanical_accessed012225.csv`\

## usage

### data processing

The core preprocessing pipeline is implemented as three Python scripts that can be run from the terminal **or** cell-by-cell in VS Code (cells are delimited with `# %%`).

- **`0_clean_names.py`**\
  Cleans botanical/species names using the resolver workbook, then subsets the WCA dataset to the CUFI top species list. Writes a cleaned subset to `data/_processed/` and unmatched-name backlog tables to `data/_reports/`.

``` bash
    python scripts/py/0_clean_names.py \
      --data-dir data/_raw \
      --out-dir data/_processed \
      --input-csv wca_All_SpeciesBotanical_accessed012225.csv \
      --resolver-xlsx TreeNameResolver.xlsx \
      --top200-csv cufi_top_200_species_in_california.csv \
      --out-csv wca_name_resolved.csv \
      --log-dir data/processing-log \
      --report-dir data/_reports
```

- **`1_quality_control.py`**\
  Applies quality control filters and standardizes units (DBH→cm, Height→m), removes invalid records, resolves species consistency constraints, and computes tree age where possible. Writes the filtered dataset and a removals dataset to `data/_processed/`, plus a removals summary table to `data/_reports/`.

``` bash
    python scripts/py/1_quality_control.py \
      --data-dir data/_processed \
      --out-dir data/_processed \
      --input-csv wca_name_resolved.csv \
      --clean-out wca_filtered.csv \
      --removed-out wca_removals.csv \
      --log-dir data/processing-log \
      --report-dir data/_reports
```

- **`2_anomaly.py`**\
  Merges remotely sensed canopy widths (`data/_raw/canopy_data.csv`), then runs Isolation Forest **per species** on DBH–height, age–DBH–height, and DBH–height–canopy combinations to compute anomaly scores and outlier flags. Writes an annotated dataset to `data/_processed/` and summary tables to `data/_reports/`.

``` bash
    python scripts/py/2_anomaly.py \
      --data-dir data/_processed \
      --out-dir data/_processed \
      --input-csv wca_filtered.csv \
      --out-csv wca_filtered_annotated.csv \
      --threshold 0.85 \
      --min-points 5 \
      --log-dir data/processing-log \
      --report-dir data/_reports
```

Optional: run without auto-changing directories (skip `.git` search)

```         
python scripts/py/0_clean_names.py --no-chdir-repo-root
python scripts/py/1_quality_control.py --no-chdir-repo-root
python scripts/py/2_anomaly.py --no-chdir-repo-root
```

- **`3_make_public_data.py`**\
  Builds the public release from `data/_processed/wca_filtered_annotated.csv`: keeps only the columns the R analysis reads, drops latitude/longitude and internal join keys, and refuses to write if any location column survives. Writes `_zenodo/wca_inventory_public.csv`.

``` bash
    python scripts/py/3_make_public_data.py
```

- **`scripts/build-zenodo.sh`**\
  Assembles the Zenodo deposition in `_zenodo/` (public CSVs, data dictionary, unmodified USFS archive, `description.txt` with checksums) and fails if any file carries a location column or a private intermediate.

### Reproducing results from the public data

Download the [Zenodo deposit](https://doi.org/10.5281/zenodo.22236551) and place its contents in `_zenodo/` at the repo root. Unzip `usfs-rds-2016-0005.zip` and copy the three tables the comparison analysis reads (`TS1_Regional_information.csv`, `TS3_Raw_tree_data.csv`, `TS6_Growth_coefficients.csv`) from `RDS-2016-0005/Data/` into `data/_raw/`. Then, in R from the repo root:

``` r
INVENTORY_CSV <- "_zenodo/wca_inventory_public.csv"   # use the public release
source("scripts/r/make-partitions.R")
source("scripts/r/dbh-ht-model.R")
source("scripts/r/age-dbh-model.R")
source("scripts/r/age-ht-model.R")
source("scripts/r/dbh-canopy-model.R")
```

The comparison-analysis scripts below then run unchanged.

### modeling (R)

Run the Python preprocessing pipeline first (through `2_anomaly.py`), then generate the train/test partitions with `make-partitions.R`. All four model scripts read from the resulting `data/_processed/wca-partitions.RData`.

The partition file **retains repeated measures**, so that `dbh-growth-rates.R` and the comparison analysis can compute growth from successive measurements of the same tree. Repeated measures must never enter a model fit: each model script collapses to one record per tree immediately after loading, under a fixed seed (22626) so that every model draws the same record per tree and runs are reproducible.

``` r
source("scripts/r/make-partitions.R")  # run once; creates data/_processed/wca-partitions.RData
source("scripts/r/dbh-ht-model.R")
source("scripts/r/age-dbh-model.R")
source("scripts/r/age-ht-model.R")
source("scripts/r/dbh-canopy-model.R")
```

#### Partitioning (`make-partitions.R`)

- Input: `data/_processed/wca_filtered_annotated.csv`
- Filter: species with ≥ 100 observations, DBH \> 2.54 cm; **all records per tree retained**
- Output: `data/_processed/wca-partitions.RData` (contains `wca_train` and `wca_val`, 80/20 stratified by species, split by `tree_id` so every record for a tree stays on one side of the split)
- Repeated measures are removed downstream, at load time in each model script, not here
- Also computes `growth_qc_pass`, a per-tree growth-rate quality screen. Successive measurements imply a DBH growth rate; a tree passes only if every interval is plausible (growth ≤ 4 cm/yr and non-zero, gap ≤ 2 years, DBH increasing). Trees with fewer than two dated measurements cannot be screened and do not pass. Computed once here so every model shares one definition of a clean tree; the age-based models filter on it

#### DBH-height (`dbh-ht-model.R`)

- Input: `data/_processed/wca-partitions.RData`
- Filter: non-anomalous records (`dbh_height_is_anom == FALSE`)
- Outputs:
  - figures → `_img/dbh-ht/`
  - results → `rslt/dbh-ht/`
- Saves: fitted `lmer` model object (`.rds`), paginated species/genus plots and diagnostics (`.png`), coefficient tables (`.xlsx` and `.rds`), scaling rate comparison plots across genera and species, and an RMSPE comparison plot against a species-specific model selection approach

#### Age-DBH (`age-dbh-model.R`)

- Input: `data/_processed/wca-partitions.RData`
- Filter: `growth_qc_pass`, species with ≥ 30 observations, non-anomalous records, non-missing age
- Outputs:
  - figures → `_img/age-dbh/`
  - results → `rslt/age-dbh/`
- Saves: fitted `lmer` model object (`.rds`), paginated species plots (`.png`), coefficient tables (`.xlsx` and `.rds`)

#### Age-height (`age-ht-model.R`)

- Input: `data/_processed/wca-partitions.RData`
- Filter: `growth_qc_pass`, species with ≥ 30 observations, non-anomalous records, non-missing age and height
- Outputs:
  - figures → `_img/age-ht/`
  - results → `rslt/age-ht/`
- Saves: fitted `lmer` model object (`.rds`), paginated species plots (`.png`), coefficient tables (`.xlsx` and `.rds`)

#### DBH-canopy width (`dbh-canopy-model.R`)

- Input: `data/_processed/wca-partitions.RData`
- Filter: species with ≥ 100 observations, non-anomalous records, valid canopy width
- Outputs:
  - figures → `_img/dbh-canopy/`
  - results → `rslt/dbh-canopy/`
- Saves: fitted `lmer` model object (`.rds`), paginated species plots (`.png`), coefficient tables (`.xlsx` and `.rds`)

## contribution plan

1.  **Keep raw data out of version control.**\
    Store local-only inputs in underscore-prefixed directories (e.g., `data/_raw/example_data_file.csv`). Contributors should coordinate a shared external location for required inputs (e.g., Google Drive/OneDrive) and provide clear instructions for syncing locally. The simplest pattern is a single compressed archive that can be unzipped into `data/`.

2.  **Prefer scripts for reproducible data processing.**\
    Contributors should develop and maintain scripts (not notebooks) that generate the processed inputs needed for downstream work under `data/_processed/`. With rare exceptions, these scripts should be the only code that reads from raw, untracked inputs (e.g., `data/_raw/`).

3.  **Use consistent, simple filenames.**\
    Avoid date/version suffixes and uppercase letters in filenames. Separate words with `-` or `_`.

4.  **Make commits small and issue-focused.**\
    Don’t push bundled, unrelated changes. Keep commits scoped to a single issue/task and use clear, specific commit messages.

5.  **Avoid hardcoding private/local paths.**\
    Scripts and notebooks should not reference personal directories. As a rule, pipeline inputs/outputs should live under `data/_processed/` (and raw inputs under `data/_raw/`). Clear notebook outputs before committing (e.g., `jupyter nbconvert --clear-output --inplace notebook.ipynb`) so no data rows are saved in the repository.

6.  **Treat notebooks as documents.**\
    Use notebooks only when (i) narrative explanation alongside code execution is the goal, or (ii) drafting figures/text for publication. Otherwise, prefer scripts.

7.  **Track execution issues in GitHub.**\
    Document errors or workflow problems as GitHub issues and tag the relevant contributor(s).

8.  **Keep the README current.**\
    When scripts, filenames, or directory conventions change, update the README accordingly—especially the data-processing usage examples and any required input/output file lists.
